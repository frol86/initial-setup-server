# Initial Server Setup

Интерактивная первоначальная настройка Debian/Ubuntu.

## Основной скрипт

```bash
curl -fsSL https://raw.githubusercontent.com/frol86/initial-setup-server/main/setup_server.sh -o setup_server.sh
bash setup_server.sh
```

Сохраняет существующие возможности: hostname, swap, mc, UFW, Docker и AmneziaWG Easy. **Дополнительно спрашивает, нужно ли настроить SSH (по умолчанию — нет).** Если выбрать «да», после основной установки запускает первый, безопасный этап SSH-hardening: создание пользователя, sudo и authorized_keys. Если выбрать «нет», SSH не меняется. Настройка UFW учитывает фактический SSH-порт: указание нового порта для firewall **само по себе не меняет порт SSH**.

## Защита SSH (отдельный интерактивный скрипт)

Под root:

```bash
curl -fsSL https://raw.githubusercontent.com/frol86/initial-setup-server/main/ssh-hardening.sh -o ssh-hardening.sh
bash ssh-hardening.sh
```

При отдельном запуске скрипт спрашивает имя пользователя, порт SSH, режим sudo и предлагает сразу вставить публичный SSH-ключ. При запуске через `setup_server.sh` SSH-порт используется **тот же, который был выбран один раз для UFW/SSH**, без повторного вопроса. SSH-модуль теперь **встроен в `setup_server.sh`**, второй файл скачивать не требуется. Можно отказаться: создаётся пустой `/home/USER/.ssh/authorized_keys`, который затем заполняется вручную. Первый этап **не отключает текущий root-доступ и не меняет работающий SSH**.

После добавления публичного ключа под root запусти:

```bash
initial-ssh-hardening --finalize
```

Скрипт проверит ключ, создаст конфигурацию с `PermitRootLogin no`, `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `AuthenticationMethods publickey` и применит порт. В Ubuntu с `ssh.socket` он переключит службу на `ssh.service`. Перед изменением создаётся systemd-таймер **автоматического отката через 5 минут**.

**Не закрывая старое подключение**, открой новую SSH-сессию:

```bash
ssh -p YOUR_PORT YOUR_USER@SERVER_IP
```

И **из новой сессии** обязательно выполни:

```bash
sudo initial-ssh-hardening --confirm
```

Подтверждение остановит откат. Иначе предыдущие SSH-настройки будут восстановлены автоматически.

### Дополнительные команды

```bash
sudo initial-ssh-hardening --status
sudo initial-ssh-hardening --rollback
```

### Важные ограничения

- Пароль root для локальной консоли провайдера не блокируется.
- Если в панели хостера включён отдельный firewall, **до финализации открой выбранный SSH-порт там**.
- Если UFW активен, скрипт добавит правило для нового порта, сохраняя старое. Удалить старое правило после подтверждения можно отдельно.
- Не рекомендуется выполнять на сервере с нестандартными `Match`, `AllowUsers`, `AuthorizedKeysCommand` и другими сложными SSH-политиками без проверки.
- Пользователю, выбирающему sudo с паролем, придётся задать локальный пароль; SSH-вход по паролю всё равно будет выключен.
- Держи открытой консоль провайдера и исходную SSH-сессию, пока новый доступ не подтверждён.

## Полная установка и SSH

В `setup_server.sh` настройка SSH опциональна. Если ключ вставлен во время установки, основной скрипт предлагает немедленно активировать SSH с 5-минутным автооткатом. Затем необходимо открыть **новое SSH-подключение** и выполнить `sudo initial-ssh-hardening --confirm`. Пока подтверждения нет, итоговая сводка явно сообщает, что SSH требует подтверждения. Если файл `authorized_keys` оставлен пустым, активация не происходит: после добавления ключа вручную запусти `sudo initial-ssh-hardening --finalize`, затем подтверди новое подключение. Старый SSH-доступ до активации не изменяется.

## Совместимость AmneziaWG

Установщик проверяет доступность NAT через `iptables-legacy` на хосте. При его доступности оставляет оригинальный образ. Если legacy NAT недоступен, но NAT через системный `iptables` работает, собирает локальный `amnezia-wg-easy:nft` на базе исходного образа, переключая `/etc/alternatives/iptables` на `/sbin/iptables-nft`. Для существующих контейнеров автоматического пересоздания нет. Проверка NAT на хосте не заменяет проверку реального VPN-трафика.
